# KIRO: рассылки (`kiro-mailer`)

Лёгкий плагин для Remnawave Minishop (plugin API v1, Minishop 3.8.0+): одноразовые Telegram-рассылки.

## Возможности
- **Получатели.** Группы (все, активные, истекшие, кончается через 7 дней, никогда не было подписки, пробный период, платившие, не платившие), тарифы, группы Minishop и других плагинов, свои условия (13 фильтров), ручной список (ID, Telegram ID, @username), сохранённые списки, исключения (люди, списки, получившие другую рассылку). **Живой счётчик**: сколько получат и почему кто-то не получит (забанен, нет Telegram, заблокировал бота).
- **Планирование.** Сразу или в указанное время (по вашему часовому поясу), снятие с планирования, пауза, продолжение, отмена.
- **Медиа.** Фото, видео, GIF, файлы, альбомы (до 10), загрузка частями до 50 МБ; Telegram запоминает `file_id`, повторные отправки мгновенные. Длинный текст автоматически уходит отдельным сообщением перед медиа.
- **Кнопки.** До 4: ссылка или раздел Mini App.
- **Опросы.** Обычный, с несколькими ответами, викторина (правильный ответ и пояснение), закрытие через N часов. Всегда неанонимные: видно, кто что ответил.
- **Статистика.** Прогресс, доставлено, ошибки, заблокировали бота, причины недоставки, скорость и оставшееся время, журнал по получателям с поиском и фильтрами, повтор для неудачных, результаты опроса, выгрузка CSV.

## Как это работает
Получатели фиксируются в момент отправки. Периодическая задача (раз в минуту) стартует запланированные рассылки и отправляет сообщения порциями с ограничением скорости. Каждому получателю хранится число уже доставленных частей (текст, опрос), поэтому повтор после сбоя не дублирует сообщение. Голоса опросов приходят через роутер бота (`poll_answer`).

Таблицы: `ext_kiro_mailer_{settings,media,lists,mailings,recipients,votes}`.

```
tests/run_tests.py     69 проверок на временном PostgreSQL (pip install pgserver sqlalchemy[asyncio] asyncpg)

```
